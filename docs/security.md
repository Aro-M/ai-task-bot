# Security

One-time eight-digit Telegram login codes are hashed, single-use and expire after five minutes. A signed 15-minute JWT is stored in an HttpOnly cookie, secure under production settings and SameSite strict, scoped to `/api`. No passwords or production demo bypass exists. Every data endpoint derives the owner server-side, checks it in PostgreSQL and returns 401 for absent/expired sessions and 403 for foreign records. Logout clears the browser cookie; a copied JWT remains valid until expiry unless the account is deleted.

Origin validation protects mutating cookie-auth requests; CORS allows only FRONTEND_ORIGIN. Bot messages/commands are bounded to 60 per user per sliding minute using indexed PostgreSQL replay receipts; the first excess message warns once. Admission is serialized and does not depend on Redis. Account deletion removes receipt ownership while retaining global replay IDs. API/login/AI quotas fail closed when rate-limit Redis is unavailable. Nginx caps request bodies at 64KiB; bot direct ingress also bounds streamed input. ORM parameters, validated enums/lengths/UTC datetimes and literal escaped searches protect input boundaries. Text is rendered by React as text; no user HTML is executed. Next exports are served with exact build-time script hashes in CSP. TLS/HSTS and private network access are operator responsibilities; only loopback frontend is published by Compose.

Audio is untrusted: metadata + real decode inspection, size/duration/MIME limits, path validation, fixed Telegram host, no redirects, subprocess argument arrays/restricted protocols, private temporary directories and bounded RAM storage. OpenAI input is only validated audio, never secrets or executable instructions. There is no tool-executing LLM. Empty/unsupported/low-confidence/silence-like transcripts cannot create tasks.

Application logs whitelist stable event names, IDs, error types and bounded traceback locations (filename/function/line only), never exception text/source/local values/transcripts/tokens. Database parameter hiding is enabled. Upstream platform logs need independent production retention controls. `.env` stays ignored; production rejects missing/placeholder/short signing and webhook secrets and nonofficial provider hosts. Runtime Python/Nginx use non-root users, no-new-privileges and private DB/Redis networking. Secrets are not baked into images.

Run `make test-security test-containers` for dependency/static/Dockerfile/Trivy lock-file checks, plus the offline Gitleaks source/history checks in CI. Lock-file scans do not establish that base images contain no OS CVEs; scan the exact deployment image/digest with an up-to-date database before release. Real provider, TLS edge, backup and hosted release permissions remain staging checks. At-least-once notifications may repeat after an ambiguous network/crash boundary while tasks stay unique.

Free local mode is explicit and development-only. It overrides the provider endpoint/key for every Python role, preventing accidental paid-provider calls, and never edits the operator .env. The local inference service has no host port, no secrets, UID 10001, read-only root/model mounts, dropped capabilities, bounded tmpfs and 1GiB/two-CPU limits. A one-shot initializer writes only the public model cache volume, checking pinned model/sample hashes. Do not expose this unauthenticated development speech server publicly. Runtime speech text is not printed by the configured server; `--print-realtime`/debug flags are not enabled.
